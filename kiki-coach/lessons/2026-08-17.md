## Concept
En un equipo de 2 personas, git rebase y git merge se usan para cosas distintas. Merge preserva la historia real (cuando se fusiono, que se fusiono, que conflictos se resolvieron). Rebase reescribe la historia para que parezca que tu feature branch salio del ultimo commit de main — lineal, limpia, "como si hubieras escrito todo en orden". El trade-off: rebase cambia el SHA de cada commit, asi que nunca rebasees commits que ya estan en main (eso destruye el trabajo de tu co-founder).

## Worked example
En paragu-ai-platform, antes de abrir PR:

```bash
git fetch origin
git rebase origin/main   # reescribe tu branch sobre el ultimo main
git push --force-with-lease origin feature/nexa-es-titles
```

--force-with-lease (no --force) protege contra pisar un push paralelo.
