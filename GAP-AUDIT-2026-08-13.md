## 2. P0 — Blocking the self-running org

### Gap 1.1: 3 cron jobs in error state (CRITICAL)

**Affected jobs**:
- `morning-brief` — error: `RuntimeError: Skipped to prevent unintended spend: global inference config drifted since this job was created (provider 'minimax-oauth' -> 'custom'; model 'minimax-m3' -> 'primary')`
- `thesis-daily-tick` — same model-drift error
- `aiw-dashboard-refresh` — error: `Script not found: /opt/data/scripts/render-dashboard.py`

**Root cause**:
- (model-drift) Hermēs has a "drift guard" that prevents jobs from running if the global model config changed since the job was created. The pin to `minimax-m3` was applied but the job's own `provider_snapshot`/`model_snapshot` didn't get updated.
- (script path) The cron job's `script` field is set to `render-dashboard.py` (no path) and the workdir is missing, so the agent runtime looks for the script at `/opt/data/scripts/render-dashboard.py` instead of `/opt/data/agents/dashboards/render-dashboard.py`.

**Fix**:
1. For model-drift jobs: re-pinned (`hermes cron update`), but the drift guard still doesn't accept the re-pinned value. Need to either clear `provider_snapshot`/`model_snapshot` manually or disable the drift guard for trusted pinned jobs.
2. For dashboard-refresh: update the cron job to use `script: /opt/data/agents/dashboards/render-dashboard.py` and `workdir: /opt/data/agents/dashboards`.

**Verified next step**: I'll patch `jobs.json`:
```python
# Clear drift guard for the 2 affected jobs
del job['provider_snapshot']
del job['model_snapshot']
# Fix dashboard-refresh script path
job['workdir'] = '/opt/data/agents/dashboards'
job['script'] = '/opt/data/agents/dashboards/render-dashboard.py'
```

## 3. P1 — Degrade quality, don't block

### Gap 2.1: No state-file schema validation

**Current state**: Each dept agent's prompt says "write to state/<dept>.json" but no schema is enforced. If an agent writes malformed JSON, the next reader crashes.

**Risk**: A malformed state file silently breaks downstream dashboards, sister agents, and history aggregations.

**Best practice** (from Inference Systems article on state snapshot integrity):
- "Validating the integrity of memory structures, execution context, and tool-calling history is a critical health check within recursive error correction frameworks."

**Fix**: Create `/opt/data/agents/state/SCHEMAS.md` documenting each dept's expected JSON shape, then add a `validate_state_files.py` script that runs as a cron watchdog and alerts on schema violations.

### Gap 2.2: No handoff matrix

**Current state**: `ORG-AGENTS.md` exists but only contains a department directory + decision rights. No explicit handoff matrix.

**Risk**: When a sales-pipeline agent discovers a legal/compliance issue, it doesn't know who to tell. Today it would just surface in the next morning brief, losing days.

**Best practice** (from CIO article on institutional sovereignty):
- "Decision rights fragment, continuity breaks, and external actors shape the agenda more than internal governance. AI amplifies that weakness because AI turns decisions into workflows, and workflows into automated action."

**Fix**: Add a handoff matrix table to `ORG-AGENTS.md`:

| From → To | Trigger | Mechanism |
|-----------|---------|-----------|
| sales → finance | Deal >$500K signed | Append to `finance.json` `pending_actions` |
| engineering → people | Contractor >30d tenure | Append to `people.json` `contractor_concerns` |
| research → operations | Publication deadline missed | Append to `coord.json` `stuck_items` |
| operations → (any) | Daily review | Daily 06:00 briefs |

### Gap 2.3: No rollback path

**Current state**: When an agent writes a bad state file, the only recovery is git history (if committed) or a manual restore.

**Risk**: A single bad write could corrupt weeks of state.

**Fix**: Add a `pre-write` hook in agent prompts: "Before writing to state X, copy to state X.bak.{timestamp}. If write fails, restore from .bak."

Cheaper alternative: cron a `state_snapshot.py` that copies all state files to `/opt/data/agents/state/snapshots/{date}/{file}` every 6 hours. Recover by copying back.

### Gap 2.4: HTTP server runs as root + no TLS

**Current state**: `dashboard-server.py` runs as root (the Hermes sandbox runs as root). Listens on `0.0.0.0:8765` plaintext. Token auth is the only protection.

**Risk**: If the host is internet-facing, anyone who scans port 8765 can:
- Brute-force the token (29 chars = ~10^40 entropy = safe against brute force in practice)
- Exfiltrate the org's full state (commercial secrets: pipeline, MRR, deployed sites)

**Fix**:
1. **Immediate**: Bind to `127.0.0.1` only (instead of `0.0.0.0`); require SSH tunnel for remote access
2. **1 day**: Run behind Caddy or nginx with TLS + HTTP basic auth
3. **1 week**: systemd unit with sandboxed user, no shell access

### Gap 2.5: No alerting on error state

**Current state**: 3 cron jobs are in error state. The user has to actively check the dashboard to discover this.

**Best practice** (from Odown article on cron monitoring):
- "Cron jobs run silently in the background. If they fail, you might not know until it's too late."
- Heartbeat monitoring (Healthchecks.io pattern) is the gold standard.

**Fix**: Add a `aiw-cron-heartbeat` cron job that runs every 30 min:
1. Reads `jobs.json`
2. For each job with `last_status == 'error'`, posts to the user's origin chat: "⚠️ 3 cron jobs in error: morning-brief, thesis-daily-tick, dashboard-refresh"
3. For each job with `last_run_at < now - 7d`, escalates: "⚠️ Job X hasn't run in 8 days"

## 4. P2 — Nice to have

### Gap 3.1: Dashboard accessibility

**Current state**: HTML is generated; no `aria-label`, no `role`, no semantic HTML, no skip-nav, no contrast guarantee.

**Risk**: User is autistic (per ops-discipline skill). Visual contrast, motion, and clutter are real concerns. Today the dashboard is dark mode only, no high-contrast option, no reduce-motion query.

**Fix**: Add `prefers-reduced-motion`, `prefers-color-scheme`, `aria-*` attributes, and a high-contrast theme switcher.

### Gap 3.2: No on-call rotation

**Current state**: When a P0 alert fires, it goes to whoever's connected to the chat.

**Fix**: Document a primary/backup rotation in `/opt/data/agents/ON-CALL.md`. Ivan = primary, Kiki = backup. Cycle monthly.

### Gap 3.3: Trademark banlist not mechanically enforced

**Current state**: Memory entry has the banlist (33+ terms). Manual compliance only.

**Fix**: Add a pre-commit hook that greps the staged diff for any banned term case-insensitively. Blocks the commit with a clear error.
