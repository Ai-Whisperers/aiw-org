## Concept

En Next.js 16 App Router, un stack trace de producción tiene **tres anillos** y tenés que leerlos de afuera hacia adentro, no al revés:

1. **El error message** (primera línea). Te dice *qué* se rompió. Acá no hay código todavía, solo el síntoma.
2. **El frame "user code"** (la línea con `app/...` o `components/...`). Te dice *dónde* en TU código se rompió. Este es el único frame que vos podés arreglar.
3. **Los frames de Node/Next internals** (`next/dist/...`, `node:async_hooks`, `node:internal/...`). Son el *cómo*. No los toques, no los busques en Google a las 2 AM — son la forma que tiene el framework de reportar el error, no la causa.

El error típico es bajar hasta el frame más profundo creyendo que "más profundo = más importante". En App Router casi siempre es al revés: el frame más profundo es un wrapper de Next, y la causa real está 5-10 frames más arriba, en tu `page.tsx` o `route.ts`.

## Worked example

En `apps/tsuki-restaurante/app/pedidos/page.tsx` (paragu-ai-platform), si tu `fetch` a la API de pedidos falla en build time y la página se rompe con:

```
Error: Fetched product data is missing required fields
    at validateOrder (app/pedidos/order-client.tsx:42:18)
    at handleSubmit (app/pedidos/order-client.tsx:87:9)
    at processSubmissions (node_modules/next/dist/server/app-router/.../server-action.js:312:14)
    at runWithDispatcher (node:internal/async_hooks:.../async_hooks.js:...:14)
```

**Lectura correcta**:
- Mensaje → "Fetched product data is missing required fields". Síntoma.
- Primer frame user-code → `order-client.tsx:42` (`validateOrder`). Acá está la causa.
- Frames `next/dist/...` y `node:internal/...` → ignorar. Next te está diciendo "yo llamé a tu función desde acá", no "el bug está acá".

Acción: abrís `order-client.tsx:42` y revisás qué campo falta en el payload. Los frames de Node no te dicen nada útil para arreglar.

## Stretch

Hacé el mismo ejercicio pero forzando un error dentro de un Server Action (`'use server'`). Notá cómo el stack trace tiene **dos** partes — la del server (donde se ejecuta la action) y la del client (donde se llamó). El frame que arregla el bug está en la parte del server, aunque el error se vea primero en el browser.
