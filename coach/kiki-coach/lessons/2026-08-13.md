# Kiki Lesson — 2026-08-13 (Fri)

## Concept
En un equipo de 2 personas, `git rebase` y `git merge` se usan para cosas distintas. **Merge** preserva la historia real (cuándo se fusionó, qué se fusionó, qué conflictos se resolvieron). **Rebase** reescribe la historia para que parezca que tu feature branch salió del último commit de main — lineal, limpia, "como si hubieras escrito todo en orden". El trade-off: rebase cambia el SHA de cada commit, así que nunca rebasees commits que ya están en main (eso destruye el trabajo de tu co-founder).

## Worked example
En `paragu-ai-platform`, antes de abrir PR:

```bash
git fetch origin
git rebase origin/main   # reescribe tu branch sobre el último main
git push --force-with-lease origin feature/nexa-es-titles
```

`--force-with-lease` (no `--force`) protege contra pisar un push paralelo.

## Exercise (<90 min)
1. Creá una branch `practice/rebase-demo` desde main en tu sandbox
2. Hacé 3 commits en la branch
3. Mientras tanto, hacé un commit en main desde otra branch
4. Volvé a `practice/rebase-demo` y corré `git rebase main`
5. Resolvé el conflicto (si hay) con `git status` + editar + `git add` + `git rebase --continue`
6. **Deliverable**: PR de práctica en cualquier repo de `Ai-Whisperers/*` con el mensaje "practice: rebase demo"

## Stretch
Repetí el ejercicio usando `git merge --no-ff main` en lugar de rebase. ¿Cuál diff te parece más legible? ¿Por qué?
