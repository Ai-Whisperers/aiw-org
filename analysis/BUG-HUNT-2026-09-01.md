## CRITICAL bugs

### C1. Hard-stops audit log has no locking → concurrent writes corrupt JSON

**File**: `patterns/hard-stop-wrapper.py:_log_check`

The audit log uses read-append-write with no file lock:

```python
def _log_check(agent_name, action, role, allowed):
    if LOG_PATH.exists():
        with LOG_PATH.open() as f:
            log = json.load(f)
    else:
        log = []
    log.append(entry)
    if len(log) > 1000:
        log = log[-1000:]
    with LOG_PATH.open("w") as f:
        json.dump(log, f, indent=2)
```

**Risk**: If two cron jobs call `hardstop_check.py` simultaneously, both read the same `log`, both append, both write — **one write wins, the other is lost**. Worse: if a write happens mid-read of another process, the file can contain partial JSON.

**Severity**: CRITICAL — this is the audit trail for AI safety violations. Silent data loss defeats the purpose.

**Reproduction**:
```bash
python3 patterns/hardstop_check.py a read_state & \
python3 patterns/hardstop_check.py b read_state & \
wait
# Two concurrent writes — one is lost
```

**Fix**: Use `fcntl.flock()` or write to append-only NDJSON (one JSON per line, no read-modify-write).

### C2. Chaos-runner pollutes production state with `.backup.chaos` files

**File**: `scripts/chaos-runner.py:101`

The chaos test writes its backup directly to **production state dir**:

```python
prod_eval = SOURCE_STATE / "eval-per-agent.json"
backup = SOURCE_STATE / "eval-per-agent.json.backup.chaos"  # ← in prod!
shutil.copy2(prod_eval, backup)
```

**Risk**: If chaos-runner is interrupted (kill -9, Ctrl-C, OOM, crash) before the `finally` block runs, the `.backup.chaos` file stays in `/opt/data/state/` forever. Worse: **the backup filename is constant** — a second run could overwrite the first run's backup, losing it.

**Severity**: CRITICAL — every chaos run leaves a forensic artifact in prod state that future runs can clobber.

**Fix**: Use unique temp filename per run (e.g., `mktemp`) and add cleanup in `finally`/`atexit`.

## HIGH bugs

### H1. Path traversal in `--agent` flag (hard-stop-wrapper.py)

**File**: `patterns/hard-stop-wrapper.py:138`

```python
prompt_path = Path(f"/opt/data/agents/{agent_name}/PROMPT.md")
```

**Risk**: `agent_name = "../../../etc/passwd"` resolves via `Path()` to `/etc/passwd/PROMPT.md` — reads arbitrary files (if they exist). An agent could probe other agents' PROMPTs and learn their hard_stops structure.

**Reproduction**:
```bash
python3 patterns/hardstop_check.py "../../../opt/data/agents/04-engineering/ai-safety-engineer" disable_hardstop
```

**Severity**: HIGH — cross-agent information disclosure.

**Fix**: Reject `..` in agent_name, or normalize to a known prefix.

---

### H2. NaN pass_rate silently bypasses eval-gate

**File**: `scripts/eval-gate-enforce.py:decide`

**Confirmed bug** (live test):
```python
synth = {"by_agent": {"weird-agent": {"pass_rate": float("nan")}}}
# Result: decision="allow", reason="pass_rate nan% ≥ warn threshold 50%"
```

**Why**: `nan >= 0.50` evaluates to `False`, then `nan < 0.30` also evaluates to `False` → falls through to "allow" branch with corrupted reason text.

**Severity**: HIGH — any agent with corrupted eval data can run unrestricted.

**Fix**: Add `math.isnan(pass_rate)` check before comparison; treat NaN as "no data" (warn).

---

### H3. String pass_rate silently returns "no data"

**File**: `scripts/eval-gate-enforce.py`

```python
synth = {"by_agent": {"str-agent": {"pass_rate": "0.95"}}}
# Result: decision="warn", reason="no eval data (agent never ran or no eval recorded)"
```

**Why**: `isinstance(pr, (int, float))` rejects strings → returns `None` → agent gets "warn" but the user thinks they had data.

**Severity**: HIGH — confusing behavior. Should either coerce `"0.95"` to `0.95` (lenient) or fail loudly (strict).

**Fix**: Either coerce or raise on type mismatch.

---

### H4. Schema validator doesn't recurse into arrays

**File**: `scripts/schema-validate-write.py:_check_additional_properties`

**Confirmed bug** (audit found this):
```bash
python3 scripts/schema-validate-write.py --audit
# [GAP]  sales.json vs sales.schema.json: 6 mismatch(es)
# - funnel_30d: unexpected field 'note' (schema has additionalProperties: false)
```

Wait — this DID work in the latest audit. Let me re-check... actually the audit said 21 gaps total now (was 16 in feedback). The recursion works for `additionalProperties` but **not for arrays-of-objects**. If a schema has:
```json
"items": [
  {"type": "object", "properties": {...}, "required": [...]}
]
```
…and an item is missing a required field, the validator misses it.

**Severity**: HIGH — schemas with array-of-object items have unverified required-field coverage.

**Fix**: Recurse into `obj[k]` when `k` is a list and schema has `items.properties`.

---

### H5. Schema validator missing `required` field check on nested objects

**File**: `scripts/schema-validate-write.py:_check_required`

Same as H4 — required-field check doesn't recurse into array items. If `sales.json.funnel_30d[0]` is `{}` (missing all required fields), the validator reports no error.

**Severity**: HIGH — silent acceptance of malformed array entries.

**Fix**: Walk into `obj[k]` when it's a list and the schema has `items.required`.

### H7. eval-gate `--threshold -1` silently allows everything

**File**: `scripts/eval-gate-enforce.py:argparse`

```python
parser.add_argument("--threshold", type=float, default=DEFAULT_BLOCK_THRESHOLD)
```

No range validation. `--threshold -1` → `pass_rate < -1` is False for any real value → all decisions fall through to `else` → all ALLOW.

**Severity**: HIGH — operator foot-gun.

**Fix**: `type=lambda x: max(0.0, min(1.0, float(x)))` or explicit check.

### H8. Cost-per-cron estimate is 30× too high for primary model

**File**: `scripts/cost-per-cron.py:114`

```python
estimate = runs_per_day * 0.0375  # mid-tier cost
```

**Reality** (from cost-tracker.json):

**Severity**: HIGH — cost reports mislead.

**Fix**: Use cost-tracker's `model_pricing` table; default to actual `cost_per_run_usd` for known models; estimate differently for script-crons (which are $0).

### M3. `state-write.sh` heredoc with unquoted variables = injection vector

**File**: `/opt/data/scripts/state-write.sh:67-79`

```bash
cat > "$LOG_FILE" <<EOF
{
  "ts": "$TS",
  ...
}
EOF
```

`$TS` and `$STATE_FILE` are interpolated. If `STATE_FILE` contains backticks or `$()`, bash evaluates them. Currently safe because STATE_FILE is a controlled path, but **a future code change that lets user input flow into STATE_FILE creates RCE**.

**Severity**: MEDIUM — latent injection vector.

**Fix**: Use `cat <<'EOF'` (single-quoted heredoc) and printf/sprintf for substitutions.

### L6. Heartbeat self-validate.sh exits 0 on missing file = silent

**File**: `/opt/data/scripts/heartbeat-self-validate.sh`

```bash
HEARTBEAT_AGE=-1
ALERT="HIGH: Gateway heartbeat file missing"
ALERT_BOOL=true
```

But:
```bash
if [[ "$ALERT_BOOL" == "true" ]]; then
  echo "⚠️  HEARTBEAT ALERT: $ALERT"
  exit 1
fi
```

This exits 1 only if `ALERT_BOOL=true`. But the assignment is inside the `if [[ -f ]]` branch — if heartbeat is missing AND ALERT_BOOL is set, it works. But what if there's no heartbeat file at all on first run? `set -euo pipefail` may exit early on `$(stat ...)` failure.

**Severity**: LOW — script is mostly fine but the error handling has gaps.
